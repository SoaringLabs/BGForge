# 角色详情 v1.4.0 验证

状态：代码回归通过；游戏内视觉效果由用户手动验收。

## 范围

角色详情大界面的今日、装备、背包、专业与资源、进度。
本机快照的数据采集与小界面统计保持不变。
版本号已更新为 1.4.0，尚未发布。

## 已验证

- Lua 5.1 编译与 upvalue 限制检查。
- 模拟 WoW 控件环境中的五页切换、角色切换、空快照。
- 背包搜索隐藏不匹配物品，装备选择清除旧详情。
- 部分击杀副本计为已完成，未击杀副本优先排列，保留击杀数量。
- 返回入口固定在左上角；角色行无垂直间距、共享单像素分隔线，悬停仅改变背景色而不改变边框。
- 角色头部的名称、等级/种族/职业/装等和数据快照在头像右侧组成左对齐三行信息。
- 左上返回区保持独立紧凑高度；左右 Header 不再与下方内容区重复绘制相邻边框。
- 右侧角色 Header 左缘使用 3px Rune Blue 强调线区分左右容器。
- “今日”页每列只有一个外框，内部模块零间距并以单条分隔线连接；三列标题与保留的副本统计统一在 38px 标题区垂直居中。“资源与快捷入口”不再显示含义模糊的单一时间，最新快照仍保留在角色头部。
- “团队副本”标题右侧只显示副本完成进度；周常进度仅在“周常任务”模块展示，不在副本列重复。
- “今日任务”概览与“专业日常”之间的分隔线贯穿左侧整列，不跟随内部文字的 12px 缩进。
- “今日任务”概览只显示合并后的待完成总数，不再在右侧单独重复周常；“专业日常”和“周常任务”标题分别使用与左侧标题一致的 14px 字号展示完成数/可做总数与完成数/总数，两个未完成数相加等于概览总数。
- “专业日常”固定按珠宝、烹饪、钓鱼三行展示。符合资格的任务保留完整图标、完成状态和“查看”；未学习的项目保持原 52px 行高与 32px 图标槽，以 45% 图标透明度、灰色文字和“未学习”状态降级显示，同时取消悬停和“查看”。
- 已学习但等级或技能不足的项目使用同一降级结构，展示精确门槛及“暂不可做”；旧快照无法判断时显示“未扫描”。只有符合资格且未完成的项目计入待完成数量。
- 周常改为复用未开始团本的 Blizzard 等待状态图标，18px 图标精确居中于原有 32px 图标槽；不再使用醒目的任务感叹号。
- “已有进度”最后一行下方的分组线扩展到与团队副本标题分隔线同宽；普通副本行仍保持原缩进。
- 专业名称和技能等级在图标后左对齐；右侧状态只占用自身区域，不再把专业名称视觉上推向中间。
- “专业技能”最后一个可见专业不再绘制行分隔线，只保留模块与“快速查看”之间的一条边界线。
- “专业日常”最后一行同样取消自身分隔线，只保留模块与“周常任务”之间的一条边界线。
- “今日”页泰坦余烬周进度使用与余烬数量一致的 14px 字号，并以 4px 间距贴近实际数字；未满周上限显示绿色，达到或超过上限显示红色。
- 装备与背包快捷入口保持各 64px 高、图标 32px，以两个无边框浅层 Surface 分块；整块悬停时切换底色并显示 2px Rune Blue 左侧焦点线。
- 当前角色之前的实机快照已确认珠宝完成状态；本轮固定三行与未学习降级状态仍待用户重载后复核。
- 已完成与未开始副本使用同一种行结构；Boss 分段条固定总宽度，击杀过任意 Boss 即采用完成状态，同时保留精确 `x/y`。
- Boss 分段条存在逐首领记录时严格按每个 `killed` 状态着色；仅在缺少逐首领明细时才按击杀总数顺序填充，避免非连续击杀额外点亮方块。
- 原有角色详情隐私与导航检查、角色快照模型回归；新增数据仅包含当前角色烹饪/钓鱼的技能线 ID、当前等级、上限与更新时间。

## 手动验收建议

代码回归完成后同步至本机 Titan 插件目录。本轮按用户要求不操作客户端，游戏内视觉复核留给用户回来后手动完成。
建议在客户端检查：

1. 五页字体、边距、装备长名称、附魔宝石 Tooltip。
2. 小窗口下的列表、背包与今日页滚动。
3. 有两个长 CD 的专业、首领最多的副本是否完整可见。
4. 多角色切换后的记录时间及未记录状态。
5. “今日”页是否保持待完成、周常、团队副本、资源、专业、快速查看六个清晰分区。
